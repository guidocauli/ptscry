**ptscry 0.7.3** (in preparazione) — Guido Cauli <guido.cauli@gmail.com>

### Correzioni
- `ptscry check` per le sessioni senza server (Gestione ptscry → Host → Verifica): un'installazione per un solo utente
  (`~/.local/lib/ptscry-gui/ptscry`) non è più CRIT perché il binario non è di root; si controllano invece che nessun altro
  possa modificarlo, la configurazione, la cartella delle sessioni, l'host e l'audit dell'utente.

- **`ptscry run` con il monitor** a volte (circa una volta su dieci con job brevi) usciva con 255 invece del codice del
  comando: il monitor registrava la fine della sessione prima di leggere il codice che il launcher aveva già inviato.
  Corretto (anche `wait`, i job e le sessioni dopo un `admin reexec`).
- Lettura dei file di chiave e certificato del client: solo file regolari, al massimo 1 MiB.

### Amministrazione senza sudo
- **`ptscry admin setup users ... | keys ...`** e, in ptscry-gui, **Gestione ptscry → Amministrazione** (utenti di
  ptscry, chiavi del front-end SSH): i membri di `admin_group` configurano il server locale senza sudo; lo fa il monitor,
  ogni operazione è nell'audit (`admin_setup`). Limiti per chi non è root: niente account di sistema (`-create`, UID sotto
  `UID_MIN`) né root; niente chiavi per chi è in root/sudo/wheel/admin/adm o per un altro amministratore; il file di una
  chiave lo legge il client; `~/.ssh/authorized_keys` solo se è un file dell'utente. Nuova opzione **`admin_setup`**
  (`users keys`, `users`, `keys`, `no`).
